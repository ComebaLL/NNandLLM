## О чём статья

Статья посвящена созданию системы автоматического обнаружения повреждений дорог с помощью компьютерного зрения и нейросетей. Авторы обосновывают актуальность задачи: ямы, трещины и другие дефекты повышают риск ДТП, увеличивают издержки перевозок и снижают комфорт движения.

В качестве детектора выбрана лёгкая модель **YOLOv12n** — одноэтапный детектор с небольшим числом параметров (~2,6 млн), рассчитанный на работу с видеопотоком в реальном времени. Обучение проводилось на датасете **CRDDC2022** по четырём классам дефектов:

- продольная трещина (D00);
- поперечная трещина (D10);
- «крокодиловое» растрескивание (D20);
- яма / выбоина (D40).

Модель обучалась 100 эпох с оптимизатором SGD на GPU Tesla A100 (Google Colab). По метрикам она превосходит сравнённые в статье YOLOv5s, YOLOv8s и YOLOv11s: Precision = 0,936, Recall = 0,914, mAP50 = 0,967, mAP50-95 = 0,707.

На базе обученной сети создано модульное ПО (Python, PyTorch, OpenCV, PyQt5, SQLite): захват и предобработка видео, детекция и классификация дефектов, постобработка, визуализация на экране и карте, сохранение результатов и формирование отчётов.

**Итог:** в работе показана практическая система мониторинга дорог, которая в реальном времени обнаруживает и классифицирует повреждения покрытия и помогает принимать решения по ремонту и обслуживанию.

## Отчёт специалиста по ML / компьютерному зрению

Работа Сацюка А.В. и Нижника В.Н. (ДОНИЖТ, 2025) — прикладное исследование: как автоматизировать поиск повреждений асфальта по видео и фото, не опираясь на ручной осмотр дорог.

**Зачем это нужно.** Плохое покрытие — не только «неровная езда». Оно связано с авариями, поломками подвески и шин, ростом стоимости перевозок и потерей времени из‑за вынужденного снижения скорости. Авторы ставят задачу сделать детектор, который можно встроить в уже существующий мониторинг и при этом успевать обрабатывать кадры «на лету».

**Что уже делают другие.** В обзоре фигурируют YOLO-модели для дорожных дефектов (в том числе YOLOv8s), облегчённые варианты вроде YOLO-LRDD, сценарии с камерой регистратора и даже GAN для наращивания обучающей выборки. При этом авторы справедливо замечают: часто не хватает учёта того, что на машине мало вычислительных ресурсов, нужна именно онлайн-обработка, а дефекты то и дело перекрываются тенью или другим транспортом.

**Какую сеть взяли.** Логика выбора понятна с точки зрения CV: нужен one-stage detector, который за один проход отдаёт рамку, класс и уверенность. Семейство YOLO для этого подходит. Среди свежих вариантов авторы ориентируются на YOLOv12 как на удачный баланс скорости и качества и берут самую «тонкую» модификацию — **YOLOv12n**, чтобы не раздувать число весов.

**Данные.** Обучение строится на CRDDC2022 (~47 тыс. кадров; большая часть с разметкой Train/Val, часть Test без меток у участников). Целевые типы повреждений: продольные и поперечные трещины, сетка («крокодил»), ямы. Важный технический шаг — конвертация аннотаций из PASCAL VOC в YOLO-формат с нормализацией координат, иначе сеть просто не сможет учиться на исходной разметке.

**Как учили.** Классическая постановка: SGD, 100 эпох, Colab с Tesla A100. Смотрят и функции потерь (рамка / класс / DFL), и привычные detection-метрики (precision, recall, mAP при разных порогах IoU). По описанию кривых — сеть не «разъезжается»: ошибки падают, качество растёт.

**Что получилось по цифрам.** YOLOv12n: precision ≈ 0,94, recall ≈ 0,91, mAP50 ≈ 0,97, mAP50-95 ≈ 0,71 при ~2,6 млн параметров. На том же корпусе она обходит приведённые YOLOv5s / v8s / v11s и по качеству, и по компактности (у тех обычно 9–11 млн параметров). С позиции практика это главный аргумент статьи: лёгкая модель не обязана проигрывать более тяжёлым «s»-вариантам на этой задаче.

**Не только веса, но и продукт.** Поверх сети собрано ПО с отдельными блоками: источник видео → выравнивание/калибровка → инференс YOLO → отсев ложных срабатываний → показ оператору → запись в SQLite → карта и отчёты. Стек типичный для такого пилота: Python, PyTorch, OpenCV, CUDA, PyQt5. То есть работа выходит за рамки «обучить чекпоинт» и ближе к диагностическому комплексу.

**Коротко по сути.** Статья показывает связку «компактный детектор дорожных дефектов + конвейер под реальное видео». Важные для специалиста моменты: обоснование real-time и edge-ограничений, выбор YOLOv12n, четыре прикладных класса на CRDDC2022, сильные метрики при малом размере модели и доведение пайплайна до GUI, БД и отчётности для службы ремонта.
